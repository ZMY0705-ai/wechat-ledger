# 08 LLM 选型对比：GLM vs DeepSeek

> 全部价格取自两家官方价目表（2026-09 核对）：
> - DeepSeek：https://api-docs.deepseek.com/zh-cn/quick_start/pricing
> - 智谱 GLM：https://docs.bigmodel.cn/cn/guide/start/pricing
>
> 价格会变，选型前建议再点一遍上面的链接。

## 1. 结论先行

本项目的大模型负载是：**每笔账一次「一句话 → 几个字段」的短 JSON 抽取**，外加每天一次
晨报措辞。属于典型的「**低难度、高频、极小量**」。

两家的能力都远远过剩，所以真正的差异不在「能不能做」，而在三件事：

1. **单价** —— 两家都在「一年十几块」这个量级，**不该作为主要决策依据**
2. **能不能关掉思考模式** —— 这条决定性最强，见 §4.1
3. **附属能力**（OCR / 视觉）—— M4 的图片账单用得上，见 §5

**最终建议：**

| 用途 | 选谁 |
| --- | --- |
| 每笔账抽取（**默认**） | `deepseek-v4-flash` |
| 每笔账抽取（**省钱/免费档**） | `GLM-4.7-Flash`（免费）或 `GLM-4.5-Air` |
| 每日晨报措辞 | 与抽取同一家（省一个 key） |
| 图片账单识别（M4） | `GLM-OCR` 或 `GLM-4.6V-Flash`（免费） |

**避坑**：不要用 `GLM-5.3` / `GLM-5.3-Flash` / `GLM-4.7` 做抽取 —— 官方明确这几个型号
**强制思考且不允许关闭**。

## 3. 按本项目的实际用量算钱

**假设**：每次抽取 700 输入 + 150 输出，其中系统提示词约 500 token 是稳定前缀，
可以命中缓存。每天 20 笔 → 一年约 **7300 笔**。

| 方案 | 每笔成本 | 一年 |
| --- | --- | --- |
| `deepseek-v4-flash`（全空闲时段） | ¥0.0010 | **¥7.3** |
| `deepseek-v4-flash`（全高峰时段） | ¥0.0020 | **¥14.6** |
| `GLM-5.3-Flash`（思考关不掉，实际更高） | ≥ ¥0.0007 | ≥ ¥5.1 |
| `GLM-4.5-Air` | ¥0.00054 | **¥3.9** |
| `GLM-4-FlashX` | ¥0.00006 | **¥0.4** |
| `GLM-4.7-Flash` | ¥0 | **¥0** |

再加每天一次晨报（约 2500 输入、400 输出）：

- DeepSeek ≈ ¥0.0027/天 → **¥1/年**
- GLM-4.7-Flash → **¥0**

**总结：全方案年成本落在 ¥0 ~ ¥15 之间。** 这个差距（一年一杯奶茶 vs 零）
在选型里几乎不该出现 —— 见 §4.1。

## 4. 能力对比

### 4.1 思考模式：本项目最关键的差异

抽取任务要的是**确定性、低延迟**。「一句话变几个字段」不需要多步推理，
思考模式带来的只有**延迟和多余的输出 token**。

| | DeepSeek | GLM |
| --- | --- | --- |
| 默认 | 思考开启，effort=high | 视型号 |
| 能否关闭 | ✅ 传 `{"thinking":{"type":"disabled"}}` | ✅ 5.2/5.1/5/5-Turbo/4.6/4.5 可关 |
| 强制思考型号 | 无 | ❌ **5.3、5.3-Flash、4.7、4.5V 关不掉**，传 `disabled` 会**报错** |

> **这是 DeepSeek 在本项目上唯一但很实在的优势**：最新一代模型都能关思考。
> GLM 最便宜的 `5.3-Flash`（¥0.8/2.8）恰恰是最不能用的那个。

### 4.2 结构化输出

| | DeepSeek | GLM |
| --- | --- | --- |
| `json_object` | ✅ | ✅ |
| `json_schema` 严格模式 | ❌ | ❌ |
| 官方是否给出客户端校验示例 | 未提供 | 提供（Python `jsonschema`） |

**两家都不支持 OpenAI 的严格 schema 模式**，所以 §5.2 的「提示词清单 + 服务端强校验」
两层防线对两家同样必要，不是 DeepSeek 独有的妥协。

### 4.3 接口与生态

| | DeepSeek | GLM |
| --- | --- | --- |
| OpenAI 兼容 | ✅ `https://api.deepseek.com` | ✅ `https://open.bigmodel.cn/api/paas/v4` |
| Anthropic 兼容 | ✅ `/anthropic` | ❌ |
| 上下文长度 | 1M | 1M（`5.3`）/ 200K（`4.7-Flash`） |
| 并发上限 | 2500（flash） | 按档位 |

**两家都是 OpenAI 兼容**，这是我们能把供应商做成配置项的前提。

### 4.4 已知缺陷

| | 说明 |
| --- | --- |
| DeepSeek | 官方明确承认：**「使用 JSON Output 时 API 偶尔会返回空内容」**，需重试兜底 |
| GLM | 未见同类官方声明（不代表不会发生，重试逻辑两家共用） |

### 4.5 中文口语理解

记口语话账（「午饭三十五」「打车十八块五」「老板发了五百红包」）属于两家模型的
强项区间，**实测前不必纠结，都够用**。真要比较，请用 `docs/07` §3 的 12 条回归语料
跑一遍，这是唯一有意义的比法。

## 5. 附属能力：图片账单（M4）

| 方案 | 成本 | 说明 |
| --- | --- | --- |
| **`GLM-OCR`** | ¥0.2 / ¥0.2 | 专用 OCR，输出布局信息，**性价比最高** |
| `GLM-4.6V-Flash` | 免费 | 通用视觉理解 |
| `deepseek-v4-flash-vision-exp` | ¥1.5 / ¥4.5 | 通用视觉，贵一个数量级 |

**M4 做图片账单识别时，优先用 GLM 的 OCR / 视觉档**，这一项 GLM 优势明确。
注意这会造成「抽取用 DeepSeek、OCR 用 GLM」的双 key 组合 —— 完全可行，
两者互不干扰。

## 6. 怎么切换

切换**不需要改代码**，只改 `config/bridge.json` 的 `llm` 块 + 填一个 API key。

### 6.1 用 DeepSeek（默认）

```json
"llm": {
  "provider": "deepseek",
  "baseUrl": "https://api.deepseek.com",
  "apiKeyEnv": "DEEPSEEK_API_KEY",
  "model": "deepseek-v4-flash",
  "extraBody": { "thinking": { "type": "disabled" } },
  "maxTokens": 500,
  "timeoutMs": 30000,
  "maxRetries": 2
}
```

### 6.2 用 GLM

```json
"llm": {
  "provider": "glm",
  "baseUrl": "https://open.bigmodel.cn/api/paas/v4",
  "apiKeyEnv": "GLM_API_KEY",
  "model": "glm-4.7-flash",
  "extraBody": {},
  "maxTokens": 500,
  "timeoutMs": 30000,
  "maxRetries": 2
}
```

然后把对应的 key 填进 `bridge/.env`：

```powershell
DEEPSEEK_API_KEY=sk-xxxxxxxx     # 用 DeepSeek 时
GLM_API_KEY=xxxxxxxx.xxxxxxxx    # 用 GLM 时
```

> `apiKeyEnv` 存的是**环境变量名**而不是 key 本身，所以 key 永远不落在配置文件里，
> 也就不会被误提交。

### 6.3 切换后必须验的三件事

- [ ] 抽取能返回合法 JSON（跑一遍 `docs/07` §3 的语料）
- [ ] 响应里没有多余的思考字段（说明 `extraBody` 生效了）
- [ ] 延迟可接受（微信回执要快，超过 3 秒体验就明显变差）

## 7. 一句话总结

> **钱不是问题（一年 ¥0~15），能不能关思考才是问题。**
> 默认用 `deepseek-v4-flash`；想省钱换 `GLM-4.7-Flash`（免费）；
> 图片账单用 `GLM-OCR`。三家接口都是 OpenAI 兼容，切换只是改配置。
