# 09 微信陪聊 Bot

> 目标：微信里那个记账的 bot，**也能陪你聊天** —— 记得住你说过的事，接得上话，
> 说话像个朋友，而不是「您好，请问有什么可以帮您」。
>
> 实现位置 `bridge/src/chat/`。**同一个 bot、同一个 token、同一个进程**：
> iLink 一个微信号只挂得下一个 bot，扫新的会把旧的顶掉（§2）。
> 记账链路本身一行没改，只在最前面多了一层分流（§4）。

## 1. 要什么 / 不要什么

| 要 | 不要 |
| --- | --- |
| 像微信上真人聊天：短句、口语、有自己的态度 | 客服腔、总结腔、「作为 AI 我……」 |
| 记得住人：工作、习惯、在折腾什么、上次聊到哪 | 把聊天记录原样喂给模型（费钱，还会让它编） |
| 关机再开机还记得 | 每次重启重新认识你一遍 |
| 聊天记录只留本机 | 上云、同步、第三方平台账号 |
| 看得懂语音（iLink 已转写成文字） | 图片识别（这一版不做） |
| 记账照常：一句「午饭35」还是立刻落库 | 为了聊天牺牲记账的确定性 |

## 2. 为什么必须挤在同一个 bot 里

这一节记的是一个踩过的坑，因为「再扫一个码，开个专门的陪聊 bot」听起来是最自然的做法。

**2.1 一个微信号只挂得下一个 bot。** 拿同一个微信号再扫一次码，微信里并不会多出一个
联系人——**它会把原来那个 bot 的连接顶掉**，登录时就会提示「连接新的 Bot 会解除原有的连接」。
也就是说，token 代表的是「这个微信号的 bot 身份」，不是「一个可以多开的会话」。

**2.2 那让两个进程共用一个 token 呢？更糟。** 长轮询（`POST /ilink/bot/getupdates`）
靠一个同步游标推进，**一个 token 只能给一个进程拉**。两个进程拿同一个 token 去拉，
就是互相抢消息：回复串台、消息随机丢一半，而且**不报错**——最难查的那种坏法。

**2.3 所以只剩一条路。** 一个进程、一个 token、一个对话框，接到消息后**在内部分流**。
代价是必须判断「这句话是记账还是闲聊」，而这个判断**必然有误判率**。
设计目标因此不是消灭误判，而是**把误判的代价压到不对称的那一侧**（§4）。

## 3. 架构

```
你的微信（还是那一个对话框）
   │
   ▼
bridge/src/index.js（一个进程、一个长轮询、一个 token）
   │
   └─► handler/router.js  ←── 分流在这里，六层见 §4
         ├─► handler/record.js ──► 记账服务 ──► 账本（原样，没动）
         └─► chat/ ─────────────► 模型 ──────► 一句回复
               ├─ gate.js     词法闸门 + `/聊` `/记` 强制前缀
               ├─ engine.js   人设 + 记忆 + 最近上下文 → 一次调用
               ├─ memory.js   滚动窗口 + 事实清单 + 摘要
               ├─ digest.js   攒够 12 轮，后台整理一次长期记忆
               ├─ persona.js  系统提示词（稳定前缀，为了缓存）
               └─ reply.js    剥 markdown 壳、图片兜底
                                │
                                ▼
                  data/chat-memory.json（原子写）
```

| 共享（因为只有一张嘴） | 各自独立 |
| --- | --- |
| token、`weixin.baseUrl` | 记忆文件（`chat-memory.json` 与 `weixin-context.json` 分开存） |
| `bridge/.env` 的模型 key、白名单 | 提示词与调用姿态（结构化抽取 vs 聊天） |
| `bridge/src/weixin/`（协议、去重、白名单、切分、401） | 模型参数（`chat.llm` 覆盖记账那份） |
| `parseJsonLoose`、`parseEnvFile`、`parseIdList` | 失败域（聊天挂了不碰账本） |

## 4. 一句话怎么被分流（核心）

`handler/router.js` 的 `handle()` 从上往下走，**撞到哪一层就在哪一层收口**：

| # | 判据 | 去哪 | 为什么排这儿 |
| --- | --- | --- | --- |
| 1 | 有未决草稿 | 确认 / 取消 / 补金额 | 「是」绝不能被当成闲聊 |
| 2 | `/记 xxx`、`/聊 xxx` | 强制记账 / 强制陪聊 | 闸门再准也会有你不同意的时候，得留个开关 |
| 3 | 记账确定性指令（撤销/余额/本月/今天/昨天/最近/帮助） | 本地办完，不过模型 | 「你好」在陪聊开着时转陪聊，其余照旧 |
| 4 | 陪聊指令（`/记忆` `/记住` `/重置`…） | 本地办完，不过模型 | 和记账那边同理：省钱，且不会「答得得体但什么都没做」 |
| 5 | 词法闸门：**看不出任何金额线索** | 陪聊 | 省一次抽取调用 |
| 6 | 其余 | 记账链路（模型再判一次 `is_ledger`） | 兜底 |

### 4.1 两条防线，一快一准

**第一层：词法（`chat/gate.js`）。** 只有这四种线索**一个都没有**时才判成闲聊：

| 线索 | 例子 |
| --- | --- |
| 阿拉伯数字 | 「午饭35」 |
| 钱的数词 | 两百、三十块、十几块 |
| 钱的字样 | 块钱、工资、房租、报销、红包 |
| 收支动词 | 买了、付了、存了、转账、还钱 |

原则是**宁可多判是账**。这里的误判代价是不对称的：

- 把账判成闲聊 → **这笔钱就丢了**，最坏
- 把闲聊判成账 → 它回一句「这笔多少钱？」，烦，但没损失

所以闸门写得很宽（「等了三十分钟」这种词法上很像账的也会放过去），
精细的那个判断交给第二层。

**第二层：模型（`is_ledger`）。** 进了记账链路之后，抽取提示词（`llm/prompt.js`）
会多要一个 `is_ledger` 字段，并明确写着「拿不准时填 true——宁可多问一句，也别漏记一笔」。
`handler/record.js` 看到 `is_ledger === false` 就把这句话转给陪聊。
「等了三十分钟」「我最近在减肥」这类就靠它兜住。

> 实测 10 个句子（5 账 5 聊）**判对 10 个**。
> 没配 LLM 时只剩第一层，行为与加陪聊之前完全一致——**不会更差**。

### 4.2 强制前缀

| 写法 | 效果 |
| --- | --- |
| `/聊 <内容>`、`/聊天`、`/说说`、`/chat` | 这句话一定当闲聊 |
| `/记 <内容>`、`/记账`、`/记录`、`/add` | 这句话一定当账记 |

记账指令前面带个斜杠也认：`/余额` 和「余额」是一回事。

## 5. 记忆怎么攒

### 5.1 两层，各自解决一个问题

| 层 | 内容 | 上限 | 存哪 | 解决什么 |
| --- | --- | --- | --- | --- |
| 窗口 | 最近 N 条消息原文（默认 24，一问一答算两条） | 滚动丢弃 | `chat-memory.json` | 接得上话、指代得清 |
| 长期 | 事实清单（默认上限 40）+ 一段摘要 | 靠整理收敛 | 同上 | 关机重开还认识你 |

窗口是「最近说过什么」，长期是「你是谁」。只留窗口 → 重启就失忆；
只留长期 → 接不上刚才那句。两个都要。

### 5.2 整理（digest）

攒够 `digestEveryTurns`（默认 12）轮，后台问模型一次：「把这些聊过的归并成一份事实清单」。
输入是**当时的窗口原文 + 已有清单**，输出一小段 JSON。因为它是**额外**的一次调用，所以：

- 走后台，**不给回复加延迟**
- 失败有冷却（`digestCooldownMinutes`，默认 10 分钟）——别每来一句就重试，那是白烧钱
- 模型没给出合法 JSON → 跳过这一轮，记忆不动
- 安全阀：原来有 ≥3 条事实、模型却吐出一份空清单 → 判定为抽风，**本次不更新**，
  并把计数留着下次再试（`WIPE_GUARD_FACTS`）。记忆是这个模块最不能丢的东西。

字段类型不对（不是数组、不是字符串）一律拒收。

### 5.3 手动那一路永远优先

`/记住 xxx` 写进去的事排在最前面，模型整理时也被要求「仍然成立的保留」——
你自己说的，比它总结的可信。

### 5.4 落盘

`data/chat-memory.json`，原子写（临时文件 + rename）。文件坏了当空处理，
不让一个坏 JSON 把 bot 卡死——代价是丢记忆，所以别手动编辑它。（想备份就复制这个文件。）

## 6. 人设与提示词

### 6.1 稳定前缀，为了缓存

系统提示词**只放不常变的东西**：人设 + 长期记忆。
时间不进系统提示词，它连同这一句话拼在**最后一条用户消息**前面：

```
[现在：2026-09-10 周四 21:30]
今天好累
```

好处有两个：前缀稳定 → 供应商的上下文缓存能命中（`docs/04` §9.4 同一条原则）；
模型每轮都能看到「现在几点」，而不是把昨天的时间当成今天。

### 6.2 人设三种写法（`config/bridge.json` → `chat.persona`）

| 写法 | 适用 |
| --- | --- |
| 只改 `name` / `description` | 换个人设一句话的事 |
| 改 `style`（数组，每条一行） | 调语气：话多话少、要不要调侃、用不用表情 |
| 整段 `systemPrompt` | 完全自己写；里面写 `%MEMORY%` 可以指定记忆插在哪 |

默认那套「像微信上真人聊天、1~3 句、不用 markdown、不说套话、不装人也不解释自己」
是刻意收窄过的：不这么写，模型两轮之内就会开始写小作文和 bullet list。

### 6.3 剥壳

微信不渲染 markdown，模型却总写 `**粗体**`、`- 列表`、`### 标题`。
`sanitizeReply` 在发出去之前把这些记号去掉（保留内容、只去记号），
顺带摘掉模型偶尔自报家门的「小满：」前缀。

## 7. 指令不过模型

和记账那边同一个理由：**省钱，而且不会出现「答得很得体但什么都没做」**。

| 指令 | 不带斜杠也认 | 做什么 |
| --- | --- | --- |
| `/帮助` | 帮助、指令 | 列指令（记账 + 陪聊两段一起给） |
| `/清空` | — | 忘掉最近这段对话，长期记忆留着 |
| `/重置` | 清空记忆、忘记一切 | 连长期记忆一起清掉 |
| `/记忆` | 你记得我什么 | 打印事实清单 + 摘要 |
| `/记住 xxx` | — | 手写一条长期记忆（排最前） |
| `/忘记 xxx` | — | 删掉含关键词的记忆，报条数 |
| `/人设` | 你是谁 | 打印当前人设 |
| `/重说` | 重来一遍 | 撤掉上一句回答，用同一句话重问 |

无斜杠的别名只保留**意思不会有歧义的整句**：`重来一次吧` 这种日常口语必须走模型，
不能被当成指令吃掉。

## 8. 配置

全在 `config/bridge.json` 的 `chat` 段（默认值见 `bridge/src/config.js` 的 `DEFAULTS.chat`）：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `chat.enabled` | `true` | 关掉之后，路由完全回到「只用记账」的老行为 |
| `chat.llm.model` | `deepseek-v4-flash` | `baseUrl` / `apiKey` / `extraBody` 自动继承记账那份 |
| `chat.llm.temperature` | `0.85` | 聊天要有点人味（抽取那边是 0） |
| `chat.llm.maxTokens` | `800` | 比抽取宽松得多，聊天不该被 500 截断 |
| `chat.persona` | 小满 | 见 §6.2 |
| `chat.memory.maxTurns` | `24` | 窗口大小 |
| `chat.memory.digestEveryTurns` | `12` | 攒够多少轮整理一次长期记忆 |
| `chat.memory.maxFacts` | `40` | 长期事实上限 |
| `chat.memory.digestCooldownMinutes` | `10` | 整理失败的冷却 |
| `chat.greetOnStart` | `false` | 开机主动打声招呼（日报之外的额外一条） |
| `chat.greetIdleHours` | `8` | 距上次聊天超过这么久才打招呼，免得反复重启就反复骚扰 |

`.env` 里只有两个逃生开关：`CHAT_ENABLED=0`（临时关掉陪聊）、
`CHAT_LLM_MODEL=...`（只给聊天换模型，不动配置文件）。

## 9. 本地试聊

```powershell
cd bridge
npm run say  -- "今天好累"      # 试一句（真调模型、真写记忆）
npm run say  -- "/记忆"          # 看它记住了什么
npm run chat -- --digest         # 手动整理一次长期记忆
npm run chat -- --greet          # 看看开机问候会说成什么样（不发出去）
npm run chat -- --say "..." --as <发送者ID>   # 换个身份试
```

不连微信、不写账本，只验证「人设 + 记忆 + 模型」这条链路。
身份默认取白名单里的第一个号，所以试出来的记忆跟微信里是同一份。

## 10. 成本

按每天 30 轮、窗口 24 条（约 2~3k 输入 token/轮）、回复 200 token 估：

| 模型 | 每轮 | 每天 | 一年 |
| --- | --- | --- | --- |
| `deepseek-v4-flash`（默认） | ≈ ¥0.006 | ≈ ¥0.18 | ≈ ¥65 |
| `deepseek-v4-pro` | ≈ ¥0.018 | ≈ ¥0.55 | ≈ ¥200 |
| `GLM-4.7-Flash` | ¥0 | ¥0 | ¥0 |

再加上**每 12 轮一次**的记忆整理调用（输入是当时的窗口，输出一小段 JSON），
大约是聊天本身的 10%~15%。

> 想省钱：`config/bridge.json` 的 `chat.llm.model` 换 `GLM-4.7-Flash`（免费，200K 上下文）；
> 想聊得聪明点：换 `deepseek-v4-pro`。也可以只给聊天换：
> 在 `bridge/.env` 里写 `CHAT_LLM_MODEL=...`，不动配置文件。

## 11. 已知限制

| 限制 | 影响 | 应对 |
| --- | --- | --- |
| 微信没有 typing 状态 | 模型慢的时候你看不到「正在输入」 | 关掉思考模式、回复控制在 1~3 句；实测 1~3 秒 |
| 单条上限 2000 字符 | 长回复被切成多条 | 通道层自动按换行切分（`splitMessage`） |
| 看不到图片/文件 | 只能提示「说给我听」 | 图片识别留给以后的 M4（`GLM-OCR`，见 `docs/08`） |
| 语音能用 | — | iLink 已把语音转写成文字，直接当文本处理 |
| 分流会误判 | 闲聊被当成账，会被反问一句「多少钱」 | 用 `/聊` 强制指定（§4.2）。注意方向：**只会多问，不会丢账** |
| token 会过期（401） | 突然收不到消息——记账和陪聊一起哑 | 明确告警，重跑 `cd bridge && npm run login` |
| `context_token` 会过期 | 主动打招呼可能失败 | 失败只记日志，不影响被动回复 |
| 只支持私聊 | — | 符合「陪我聊天」的需求 |
| 记忆是明文 JSON | 本机文件 | 只在本机，不入版本库（`.gitignore` 里是 `data/`） |

## 12. 排障

| 现象 | 排查 |
| --- | --- |
| 说话没反应 | 进程在跑吗；token 是否过期（日志里的 401）；白名单是否把自己挡住了 |
| 它回「我还没接上大脑」 | 没读到模型 key：确认 `bridge/.env` 里有 `DEEPSEEK_API_KEY` |
| 回复带「刚才没连上模型」 | 网络/额度问题，错误详情在同一时刻的控制台日志里 |
| 每次都说「刚走神了」 | 模型一直返回空内容：换模型，或看是否被限流 |
| 闲聊被当成账，反问「多少钱」 | 换成 `/聊 xxx`；或把 `chat/gate.js` 的动词表收窄一点 |
| 明明在记账，却被当闲聊 | 理论上不会（闸门是「宁可多判是账」）。真遇到就 `/记 xxx` 强制记账 |
| 陪聊整个不生效 | `config/bridge.json` → `chat.enabled` 是否为 true；看启动横幅的「陪聊 :」那行 |
| 答得不像人 | 调 `config/bridge.json` → `chat.persona`；或把 `chat.llm.model` 换成更强的 |
| 忘了之前说过的事 | `/记忆` 看事实清单；窗口只有 24 条，更早的靠整理留下 |
| 记忆里出现胡编的事 | `/忘记 关键词` 删掉；把 `digestEveryTurns` 调小可以让整理更勤 |
| 想从零开始 | `/重置`，或删掉 `data/chat-memory.json` |

## 13. 防翻车清单

- [ ] **绝不能因为陪聊丢账**：闸门只在「看不出任何金额线索」时才判闲聊，其余一律走记账
- [ ] 模型判 `is_ledger` 时被明确要求「拿不准就填 true」
- [ ] `/聊` `/记` 两个强制前缀兜住所有误判，用户永远能自己指定
- [ ] 未决草稿排在最前，「是」/「35」不会被陪聊截胡
- [ ] 白名单仍然只有一道：陪聊不会让陌生人拿到回复
- [ ] 指令、清空、记忆增删全在本地完成，不经过模型
- [ ] 记忆整理只允许「照抄或留空」，不让模型自由发挥
- [ ] 记忆写回前做类型校验 + 空清单安全阀 + 失败冷却
- [ ] 记忆文件原子写；坏了当空处理，不阻塞启动
- [ ] 回复统一剥 markdown，防止微信里出现一堆符号
- [ ] 整理调用走后台，绝不给回复加延迟
- [ ] 陪聊关掉、或没配 key 时，行为与加它之前**完全一致**
- [ ] 聊天不碰数据库、不调记账服务，出问题也不影响账本
